# Full source review — recovered hybrid implementation

This review covers the recovered scanner and the changes through the Windows pacing fix in e6e64a7. The source was recovered from the newest available checkpoint and compared with the preserved original and first-hybrid archives. It was not rebuilt as a replacement application. Benchmark and browser acceptance remain open until their results are reconciled; this document does not certify live TikTok compatibility.

## Browser assets, dependencies and verification code

The complete report template and browser worker were reviewed: row reconstruction, indexes, search, filters, numeric/string sort, tabs, pagination, details, relationships, avatar references, error fallback, keyboard dismissal, escaping and mobile layout. Rendering is bounded by the chosen 20–500 row page; the complete dataset remains queryable. The cooperative fallback yields between chunks, although its CPU work remains higher than the browser worker. The current 180,000-row comparison will determine measured generation/load/search/sort regressions rather than assuming them away.

Vendored signing code remains isolated under its provenance/license files. The immutable upstream archive and pre-integration evidence are preserved. CI repeated the unmodified upstream tests with real PostgreSQL/Redis: 2,529 unit/replay and 528 integration passes. Historical environment failures were not erased or attributed to this integration. This later repeat is not misrepresented as having happened before integration.

All regression modules in `run_tests.py` were reviewed along with their fixture builders. The explicit suite avoids inherited test-class duplicates. Windows excludes POSIX process-signal suites and marks the POSIX repeated-SIGINT harness skipped; Linux runs those tests. Test counts and exclusions are reported per platform, not presented as identical coverage.

Benchmark code was reviewed as production code for measurement correctness. The old hybrid harness incorrectly constructed HybridClient for Worker-only mode. Harness version 2 captures and calls the production factory. Old results remain historical and are not mixed into the current matched ratios. The loopback TLS fixture initially returned the wrong username for benchN requests; correcting the fixture resolved validation failures without weakening the scanner parser. Separate immutable source copies prevent progress commits from changing a running measurement.

GitHub workflow jobs preserve every finished case. The original/first/final throughput variants run sequentially on one runner; the network and browser jobs use other runners and do not contend with that comparison. No ratio combines different hosts. Source hashes, Python/platform, fixture configuration and measurement scope accompany the evidence.

## Synchronous work and remaining performance questions

Network I/O is asynchronous. Per-profile SQLite/export work is awaited through independent executor ownership, while shared state uses one ordered writer. Native signing uses a bounded executor; stage wall time may include executor waiting and may overlap between requests. It must not be added to total CPU time as if exclusive. The Python main-thread cProfile does not capture worker-thread CPU; explicit disk/signing timing and component measurements cover those stages separately.

Global request admission, small in-memory counter updates and short matching/lookups remain synchronous because scheduling every tiny operation would add work. SQLite durability is retained even when it costs throughput. Per-profile writes and raw exports can dominate fixtures containing many tiny accounts. Large sparse reports exercise resume/serialization differently from fully completed-account scans.

A source review cannot prove maximum possible speed, absence of every race, or production service reliability. Open performance acceptance items stay FAILED/in progress in the requirement audit until matched measurements have been reviewed. Live requests, maximum reliable Direct page size, real proxy-plan behavior and production throughput remain BLOCKED BY ENVIRONMENT without configured authorized test subjects and identities.
